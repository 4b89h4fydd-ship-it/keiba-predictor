## 1. 中央の出走表が壊れていた原因

netkeiba の出走表ページの HTML が変わり、`app.py` が古いクラス名を探していました。

| 項目 | コードが探していた旧 HTML | 現在の HTML |
|---|---|---|
| 馬番 | `td.Umaban` | なし（オッズの `span#odds-1_XX` と行の順番が馬番） |
| 馬名 | `td.HorseInfo` / `.HorseName a` | `td.Horse_Info` / `dt.Horse a`（過去走ページは `div.Horse02 a`） |
| 性齢 | `td.Barei` | `dd.Age`（過去走ページは `span.Barei`） |
| 騎手・斤量 | `td.Jockey` | `dd.Jockey`（騎手は `a em`、斤量は末尾の数値） |

そのため馬番は常に0、馬名は常に空になり、本番の D1 に「空の馬が数頭だけ」の出走表が保存されていました（当日の中央22レース中17レース）。

### 修正内容

- 新旧どちらの HTML でも読めるヘルパー `_nk_row_horse()` を追加
- `_netkeiba_detail_rows`（出走表・過去走）、`_netkeiba_card_rows_fast`、`_netkeiba_past_rows_fast` をこのヘルパーに置き換え

### 確認結果（2026-10-04 京都11R 京都大賞典）

| 項目 | 修正前 | 修正後 |
|---|---|---|
| 頭数 | 4（すべて空） | 18（全馬に馬名） |
| 例 | — | 1番 ウエストナウ 牡5 57.0 横山和 508(+4) |
| 過去走 | 0〜4件 | 各馬4〜5件 |

## 2. 過去走の斤量

`_parse_recent_cell()` が「最初に出てくる2桁の数字」を斤量にしていたため、着順が10着以上のレースでは着順が斤量になっていました。

| 過去走 | 修正前 | 修正後 |
|---|---|---|
| 中山11着 … 57.0 8-6-5-7 | 11.0 | 57.0 |
| 阪神13着 … 57.0 7-10 | 13.0 | 57.0 |

通過順の直前にある数字を斤量として読むように直しました。

## 3. 同期ワークフロー

以前の `arvexq-sync.yml` は発走中と次のレースだけを更新していたので、一度壊れた出走表がほかのレースに残り続けていました。全レース版に置き換え、さらに次の動きにしました。

- 馬名が欠けた出走表は「使えないデータ」として作り直す
- 作り直しても欠けが残れば、ワークフローを失敗にして気づけるようにする
- `app.py` を更新したときにも自動で動く

本番へは送らない形で手元で同じ処理を実行したところ、当日24レースすべてで出走表が揃い（馬名の欠け0件）、所要時間は約52秒でした（制限5分）。

## 6. 未対応：JRA 公式フォールバック

`_jra_find_cname()` は JRA トップページのリンクから当日のレース ID を探しますが、調査時点ではトップページに前日分のリンクしかなく、当日のレースを見つけられませんでした。中央のデータは実質 netkeiba だけに頼っている状態です。netkeiba がまた変わると中央が止まるため、別の取得経路を用意するのが望ましいです。

## 7. 未対応：版番号の二重管理

`build_static.py` の `BUILD_VERSION` と、`app.py` の中の `v324` を手で合わせる必要があります。ずれると画面が「ARVEXQを起動中…」のまま止まります（`AUDIT_BOOT_SYNC_FIX.txt` の事例）。将来は `app.py` 側の1か所だけで管理する形にするのが安全です。
