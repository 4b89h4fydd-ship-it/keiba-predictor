ARVEXQ v324 CORE DATA GUARD - PREDEPLOY AUDIT
Date: 2026-10-04

Problem reproduced from screenshot:
- race had horse numbers + win odds + popularity + AI marks
- horse names/jockey/carried weight were blank
- this shape was incorrectly treated as a valid detail because horses.length > 0

Root cause confirmed in v321:
1. mergeRaceReflection() can create horse skeletons from odds rows alone.
2. openRace(), fetchEdgeRace(), cache loading, and selected-race load status accepted any non-empty horses array.
3. raceReflectionIncomplete() had stricter checks but was never used.
4. v323 workflow still considered any horseNumber-only card "usable", so v323 was not sufficient for this screenshot case.

v324 replacement:
- removed the unused raceReflectionIncomplete() block.
- added one actually-used raceDisplayCoreReady() validator.
- a race card is not display-ready unless active runners have names and at least 70% have jockey + carried weight; field-size coverage is also checked.
- odds-only/horse-number-only skeletons are rejected by direct race fetch, day fallback, cache load/save, race opening, and selected-race completion counts.
- old incomplete localStorage detail rows are ignored automatically.
- full-card GitHub workflow now uses the same concept of usable core horse data.
- workflow merge uses horse-card quality so an odds-only refresh cannot overwrite a richer horse card.
- if any race remains unusable, final workflow validation reports it as missing instead of silently publishing it as complete.
