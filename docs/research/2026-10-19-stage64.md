# 第64段階：中央・地方の研究接続、外部時刻証明、凍結から採点まで

第63段階に続けて実施。既存UI・デザイン・データ取得経路・稼働中予想・
v3の本番用空モジュールは変更しない。main統合・デプロイなし。

## 実装した範囲

- `arvexq/research/stage64/`：中央・地方を別設定で実行する研究用パイプライン。
  共通の数式処理は第63段階を再利用し、中央に地方の展開補正を移植しない。
- 能力・脚質・展開・確率・印の役割・買い目選択を分離。
  印は研究用の勝ち馬候補と3着内軸を別出力し、根拠のない信頼度等級は付けない。
  仮想買い目は最大10点・重複なし。製品向けの印・おすすめ購入は未承認のまま。
- `protocol.py`：研究条件・コード・入力・出走馬・全候補を固定。
  同一レース重複、発走後作成、結果入り入力、途中失敗した部分的な凍結を拒否。
- `witness.py`：GitHub APIから実際に読み戻したartifactのSHA-256、
  リポジトリID、workflow run、完了状態とサーバー時刻を照合。
  planは対象期間開始前、全予測は各発走前にworkflowが完了していることを要求。
  入力JSONの時刻や「検証済み」フラグだけでは独立証明に昇格しない。
- `evaluation.py`：凍結全レースと結果を別プロセスで厳密照合。
  未予想レースを分母から消さず、中央・地方・日付・方式別に集計。
  払戻欠損を0円扱いせず、回収率は算出不可にする。同着の複数組番も扱う。
- 3本のCLI：保存ZIPの接続検証、計画/凍結/採点、既存保存artifactからの取得。
  いずれもレースデータを新しい取得元へ取りに行かず、DBを書き換えない。
- `arvexq-stage64-shadow.yml`：PRテストと中央・地方の計画artifact事前登録。
  将来予測の凍結は既存保存artifactを指定する手動実行のみ。定期収集や本番接続は追加しない。

1. 中央4R・5頭の取消/除外が`status`だけに保存され、真偽フラグがFalse/None。
   研究側で`出走取消`・`競走除外`も認識し、出走馬集合と結果側の集合が全527Rで一致。
2. 平地の馬にばんえい履歴が入る例があり、競走種別不一致の履歴を除外して明示。
   同名馬の誤結合か転記かは未確定。元データは書き換えない。
3. 中央の障害5Rは未対応として全対象108Rの中に残す。平地モデルで代用しない。
   地方の帯広ば36Rも別競走種別として未対応にし、全対象419Rの分母に残す。
   保存されたanalysisModeが平地でも、競馬場が帯広ばならばんえいとして判定する。

   33頭は履歴0件、別の1頭は平地と不整合なばんえい履歴3件。

## 今後の発走前検証を動かす手順

対象期間候補：2026-10-21〜2026-11-19 JST。
中央・地方を別planで事前登録し、baseline / recent5 / recent5_shrunkを変更せず並行保存。
判定には各区分100R以上・10日以上を必要条件とし、期間中に係数を選び直さない。
この件数だけで統計的有意性や長期収益性が保証されるわけではない。

1. PRのShadow Research CIが、コードハッシュに一致する中央・地方planを
   v4 artifactとして保存する。CI完了後、取得した実artifact IDを使う。
2. 同workflowの手動`freeze`に中央/地方、plan artifact、既存保存入力artifact、
   入力JSONのZIP内ファイル名を指定する。対象区分の全レースを凍結する。
   保存入力が揃わない・既に発走済みなら処理は失敗し、予測を後付けしない。
3. 結果判明後に以下を実行。GITHUB_TOKENはActionsのread権限で利用。

```bash
python scripts/arvexq_stage64_forward.py score \
  --plan-artifact PLAN_ARTIFACT_ID \
  --forecast-artifact FORECAST_ARTIFACT_ID \
  --results confirmed-results.json --output NEW_RESULT.json
```

結果JSONはraceId/circuit/date/status=confirmed/orders/payoutsの配列。
結果全件のレース集合が、凍結対象全件と完全一致しなければ拒否する。
結果ラベル自体の公式認証は別監査であり、時刻証明によって代替しない。

**外部時刻証明の意味は「指定された全レースの入力・予測の正確なバイト列が
発走前に存在した」こと。公式全開催網羅やモデルの科学的独立性まで証明しない。**
GitHubのgit author日時は使わず、artifactダイジェストとサーバーのworkflow完了時刻を使う。
完了が発走後になったもの、fork由来、欠損digest、期限切れ、内容改変は拒否。

今回、実際の未来レース予測はまだ生成していない。
独立発走前予測の新規採点実績は0R。単体テストの人工レースを成績に含めない。
将来のレース・払戻・欠測補修を現時点で完成済みとは扱わない。
